# ADR-0003: 浏览器半边靠构建期内联拆分，不用运行时模块（Build-time module inlining）

- **Date**: 2026-09-30
- **Status**: Amended by ADR-0012
- **Deciders**: YV3507
- **Amends**: 浏览器侧模块组织的实现约定（见 `docs/CODE-STRUCTURE.md`）

> 机制细节在 `scripts/build-client.mjs` 与各 `src/**` 模块的文件头；本文只记取舍。

## Context

浏览器半边的入口是 `lib/client.js`，它由 DSH 客户端加载器按**包元数据**取走，
在一个 `window.__ModuleLoader__.load({ id, factory })` 的工厂作用域里执行。

关键约束：**该加载器的 `require` 只解析外部包**（如 `react` / `react-dom`），
**不解析本地相对路径**。也就是说：

```js
import './panel-tabs.js'   // ← 运行时根本不成立
```

这不是配置问题，是加载器的设计边界 —— 它没有本地模块解析器。

与此同时，`src/client.js` 的可读性要求这个半边**必须能拆**：面板、选择器、模态框、效果应用、
实时图层、样式表各是一大块，全塞进一个文件会让"这段逻辑从哪开始"难以定位。本仓的
`src/styles.js`（全仓最大的一块纯数据）就是为可读性单独成文件的典型。

于是产生一对张力：

- **可读性**要求把 `src/client.js` 拆成多个文件；
- **运行时**没有模块系统，拆出去的东西无法 `import` 回来。

## Decision

**采用构建期内联**：`src/**` 里的模块按一张显式清单（`INLINE_MODULES`）在**构建期**
被剥掉 `export` 后按序注入 `lib/client.js` 的**同一个工厂作用域**，于是它们在运行时
就是同作用域的普通声明 —— 互相直接按名字引用，无需解析器。

配套决定：

- **D1 —— 内联模块必须浏览器安全**：不得出现 `import` / `require(` / `export default` /
  `process.*` / `__dirname` / `__filename`。构建期逐条断言，且**先剥注释再判**（否则
  注释里提一句 `require` 就会误报）。
- **D2 —— 内联模块不得有顶层可执行语句去读宿主状态**：它们被注入在 bundle **顶部**，
  早于 `src/client.js` 正文；顶层去读正文里的 `const` 会撞 TDZ。
- **D3 —— 清单必须与目录一一对上**：除正文外每个 `src/**/*.js` 都要在清单里，
  否则**不报错**，只是永远不进产物（见下"代价"）。每项还须带 `why` 与 `markers`。
- **D4 —— `markers` 是防"拆分悄悄变空"的锚点**：缺任一标记即**构建硬失败**，
  产物还必须能通过解析才会被写出。
- **D5 —— 名字必须唯一**：既然拍平进同一作用域，重复声明会被构建期提取后断言，冲突即失败。
- **D6 —— 产物入库、且永不手改**：`lib/client.js` 是生成物但**提交**（本仓支持的安装路径
  不会跑构建），`src/**` 的任何改动都要在同一提交里重建产物。
- **D7 —— `src/` 模块之间不写 `import`**：它们靠"同一作用域"协作，靠模块头写下的
  **契约**（需要什么外界、对外提供什么）而不是显式依赖。
- **D8 —— `src/` 目录不承载机器含义**：因为没有解析器、没有守卫能验证"层次"，
  建子目录的唯一收益是"让人一眼看出这几块是一伙的"。因此准入条件刻意定得很高
  （见 `docs/CODE-STRUCTURE.md`），且默认平铺。

## Consequences

**收益**

- **可读性与运行时可拆性同时满足**：源文件想怎么拆就怎么拆，运行时仍是一个作用域。
- **零运行时模块解析成本**，也不引入打包器（构建脚本只用 `node:` 内置模块）。
- 拆分是**显式登记**的：读构建清单就知道浏览器半边由哪些文件构成。

**代价（我们放弃了什么）**

- **漏登记是静默的**：这是本路线最危险的失效模式 —— 新建一个 `src/**` 文件却忘了登记，
  构建照样成功，只是那个文件永远不进产物，调用点一到运行期就变成 `ReferenceError`。
  本仓实际发生过一次（一个文件长期是孤儿），此后才补上"无孤儿"的守卫。
- **不能按需加载**：所有内联模块都进同一个 bundle，没有代码分割，包体积不可按需削减。
- **依赖关系不可见**：D7 意味着模块间的真实依赖只能靠文档和契约注释表达，
  编译器与静态分析帮不上忙。
- **注释会随包发给用户**：`src/**` 的注释进产物，所以涉及行数/体积这类会漂的量，
  要写**复算命令**而不是写数字（否则用户读到的就是过期数字）。
- **产物即契约**：多个守卫跑的是**产物**而不是源文件，所以"重建后再断言"是必须的，
  也意味着构建脚本的结构本身被下游依赖。

## 重新考虑的触发线

- 上游 DSH 客户端加载器**开始支持本地模块解析**：那么 D1–D8 的大半复杂度可以整体删除，
  应立刻回来重评（这是最可能、也最值得推翻本 ADR 的触发线）。
- bundle 体积成为用户侧首要抱怨，且代码分割成为必需。
- 内联模块数量增长到单清单难以维护：届时应先考虑**目录准入条件**是否该放宽，而不是继续平铺。
