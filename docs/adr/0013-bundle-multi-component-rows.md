## Context

### 用户口径（本决策的动机）

- 起因：「当前插件正在逐渐臃肿，我希望发起一轮大重构，将插件拆分为多个插件组成的插件包」，
  并要求参照 `dsh-ops` 的设计判定哪些功能适合独立。
- **三件核心目标（2026-10-14 重锚）**：**降复杂度 / 锚定模块边界 / 解耦合**，三者并列、互不替代。
- **开关的档位（2026-10-14 终局）**：组件行由宿主**行级**开关；关掉一行 ⇒ 该组件的**宿主路由**
  与**浏览器可见面**（界面区块 + 设置控件）都不再出现。**不含**浏览器侧每组件一格开关。
- **优先级（2026-10-14）**：**实际效果与最终成品的低复杂度、低耦合，优先于"重构过程本身的复杂度"**
  —— 为达成品语义，允许推翻此前的结论与部分测试体系。

### 可测事实（符号名 / 文件路径作锚点，不写行号与数值）

**宿主机制（`app.asar` 内 `@deepseek-ai/*` 的产物与随包文档；复算方法见 [`DSH-UI-INTERFACES.md`](../DSH-UI-INTERFACES.md)）**

1. **一个包 = 一个 bundle = 多行**：`package.json` 声明 `dsh.bundle.patch`，patch 是**顶层 YAML 数组**；
   `- insert:`（**不带 `id`**）把若干行追加到根 `include` 上，每行是一个 loader entry
   （`{ id, name, config, group, disabled }`）。行**未激活也能显示**标题 / 描述 / 图标 —— 元数据走**导出资源**
   （`readPluginMeta()` / `metaOf()` 读 `<specifier>/locale/<lang>.json` 与 `<specifier>/package.json`、
   `iconOf()` 读顶层 `icon`），**不 import 插件代码**。用户在插件管理器里单独开关某一行 ⇒
   `setPluginEnabled()` → `writePluginEnabled()`（保留注释地改 profile 的 `cordis.patch.yml`）。
   出处：宿主随包 `host-plugin.md`、`dsh-app-boot`、`dsh-host-plugin-inventory`、`dsh-plugin-manager`。
2. **`name` 与 `id` 的三种语义**：不带 `id` 的 `insert` = 顶层追加（行可直接寻址、可单独开关）；
   带 `id` 的 `insert` = 往那个 **group** 行里 push（非 group 会报错）；**非 insert** = 按 `id` 覆盖既有行，
   且覆盖时 `config` 是**整体替换、不深合并**。
3. **客户端半边是「包级」的**：`dsh-client-modules` 用 `exactPackageSpecifier()` 只认**裸包名或恰好两段的
   scope 名**，再用 `nearestPackage()` 向上找第一个 `name === 包说明符` 的清单，最后 `table.set(packageName, …)`
   ⇒ **一个包只产生一个客户端 graph row（id = 包名）、一个开关、一个 UI 贡献面**。
   子路径行（`pkg/sub`）**完全不参与** `dsh.client` 扫描。⇒ 组件行**不可能**有自己的客户端开关。
4. **`dsh.client` 字段全集** = `platform` / `inject` / `external` / `immediately`；`inject` 只是到达顺序，
   **不存在的 id 被静默跳过**。
5. **`dsh-plugin.json` 与 `patchReload` 在运行时都没有消费者**（全量检索 `.js` 零命中）；
   profile 的 `cordis.yml` **不是事实来源**（每次启动被重写），只许改 profile 的 `cordis.patch.yml`。
6. **行开关不是热切换**：`cordis.patch.yml` 住在**包目录**，不在 `dsh-hmr` 的监听面
   （监听面 = profile 的 `package.json` / `cordis.patch.yml` 与 `$DSH_HOME/cordis.patch.yml`）
   ⇒ 改行后需**重启或重载**才生效。
7. **包内懒块机制可用**（`require.async()` / `client.<name>.js` / `chunkId()` / `importChunk()`；
   上游同版本自家侧栏包有先例）：块按**当前 revision** 从包内客户端入口同目录出，文件不存在即 404
   ⇒ 块必须**逐条登记进 `files`**。它改变的是**下载粒度**，不是开关粒度（第 3 条）。

**本仓现状（拆分前）**

8. **复杂度集中在两处**：宿主门面 `lib/index.js` 里混着大量**与装配无关**的实现（Steam / WE 发现、
   转码与 ffmpeg、数据目录与 config 内核、HTTP body 内核）；浏览器半边 `src/client.js` 是最大的客户端文件，
   且浏览器半边**没有模块系统**（靠构建期内联，见 [ADR-0003](./0003-build-time-module-inlining.md)）。
   而 `lib/routes/*.js` **每个文件的入边恰好是 1**（只有门面 import 它）⇒ **路由族事实上已经是插件**。
9. **设置曾是**单一扁平命名空间且 `PUT /settings` 是**整段覆盖** ⇒ 两个组件各写一次必然互相丢键；
   `lib/settings-schema.js` 又是宿主与客户端**共用的唯一内核**（[ADR-0002](./0002-settings-schema-single-source.md)）。
10. **组件装载状态有真源**：`/diag-log` 的 `components`（`declared` / `loaded` / `started` / `failed` / `missing`）
    —— 客户端不必用"试着加载、失败再降级"来猜组件是否可用。
11. **客户端此前零状态面**：`src/**` 不读组件装载态，`/inventory` 不返回组件态；
    而组件不可用时客户端是**静默坏**（`<img>` 无 `onerror`）⇒ "行关了"与"坏了"在界面上长得一样。
12. **宿主侧另有一条边界漏口**：`lib/routes/presets.js` 直接持有立绘 / 头像的落盘路径键
    （`mascotPath` / `mascotDir` / `avatarPath` / `avatarDir` / `AVATAR_SIDES`）
    ⇒ 关掉对应组件行后，预设族照样能读写这两族资产。

## Decision

### A. 目标与判据

- **D1 核心目标三件并列**：**降低复杂度**（门面与单文件体量、门面内非装配代码占比、
  「一个功能族 → 哪些文件」的唯一性）、**锚定模块边界**（落点唯一 **且** 边界**可声明、可核对**）、
  **解耦合**（模块之间只通过公开契约通讯：显式注入面 + 内核分级面，隐式共享清零）。
  只有目录变了而没有可声明的边界，**不算锚定**。
- **D2 判据口径 = 度量 M1–M10**（定义与复算命令见 [`BUNDLE-SPLIT.md`](../wip/BUNDLE-SPLIT.md) **附录 E**）：
  复杂度 = M1 / M2 / M3 / M6 / M7；锚定边界 = M8 / M10；解耦合 = M9；守卫负担 = M4 / M5。
  **不改善任何一项的工作一律不做** —— 哪怕它能变成一个可独立开关的行；**"可开关本身不加分"**。
  **唯一例外见 D3**。
- **D3 行级开关的语义（例外条款：本条的买方理由不在 M1–M10 里）**：
  **D3①** 开关的作用域 = **宿主路由 ＋ 该组件的浏览器可见面**：停用某行 ⇒ ① 该行注册的路由**整族不注册**；
  ② 该组件声明的可见面（界面区块与设置控件）**不渲染**。
  **D3②** 可见面**由宿主行状态派生**（客户端只读，禁止在浏览器侧手写第二份"组件名 → UI"清单）；
  每个组件行的可见面落在哪些渲染函数 / 设置键上，写成**单一真源**并与实现**双向对账**
  （声明了没 gate、gate 了没声明，都要红）。
  **D3③** 失效口径三条：**宁可显示、不可静默消失**（状态面读不到 / 请求失败 ⇒ 一律按"可用"渲染；
  这与"内核缺键即抛"是不同场景的两条纪律：缺键 = 装错，探测失败 = 不许让功能凭空消失）；
  已声明的可见面缺失 ⇒ **必须有明确的不可用形态**（`<img>` 一族须有 `onerror` 兜底，禁止"破图 + 空值"）；
  **失败必须可见**（`components.failed` 与"未启用"在界面上必须可区分）。
  **D3④** 本条**只**覆盖 D3①–③ 定义的可见面工作；其它任何工作仍按 D2 判。
  D3 的落地必须配**机械判据**（见 §验收），不接受"做了但没人能验"。
- **D4 A 语义是 D3 的底座**：路由仍照旧注册 / 撤掉；D3 只**增加**可见面这一层，
  不改变"关掉 ⇒ 路由消失"的既有行为与既有判据。
- **D5 全程零行为回归、守卫继续有牙**：现有路由、全部设置键、资产（预设 / 立绘 / 字体集）与用户数据
  在每一步后都还能用；**不接受"先关掉守卫再拆"**。

### B. 形态与阶段

- **D6 终态取「多包」**（主包 + N 个子插件包，**版本一致**；**2026-10-14 用户口径改写，原为「单包多行」**）：
  安装面只有**主包一个名字**（子包作为传递依赖被 hoist，语义见手册 §2.3）；**每个包各自满足四个半边**
  （宿主实现 / 宿主行 / 浏览器半边 / 行元数据，手册 §2.2）；行仍必须**不带 `id`** 地顶层 `insert`
  （否则不可寻址、不可单独开关）；**必须保留一个 `name` 恰为裸包名的行**承载主包的浏览器半边，
  否则客户端半边**静默消失**。
  **原 D6 的形态（单包多行）是本次重构的起点、不是终态** —— 它已经落地（组件行 + D3 的开关语义），
  是下面 D7 的成果，也是多包化的前置。
- **D7 组件化之前先做库化与内核化**：先**纯搬移**（零行为变化、产物零字节变化），把门面里与装配无关的段落
  与新组件的落点定下来；`settings` 先分区（per-component 子段 + 一次性**幂等**迁移，`/settings` 改成按段合并）。
  **设置可切分是真组件的先决条件** —— 跳过它直接拆，等于把「两个组件互相丢键」写进架构。
- **D8 目标形态取「多包」（就地改写；原为"不做多包 monorepo"）**。**2026-10-14 用户拍板**，
  理由**只有一条**：**降复杂度与解耦**（用户口径：**独立发布不必要**、子包**版本一致**更方便管理）。
  **代价照付、原来记的一条不少**：发布面按包数 ×N（用"版本一致 + 子包只在主包 `dependencies` 里出现"压掉）、
  踩在宿主可能无预警变更的 `dsh.client.*` 上、构建脚本要按包循环出多份产物、守卫与生成物大面积重写
  （清单见手册 §10.1）。
  **买方理由明确排除两件事**：① "关掉即不下载"（D16）；② 浏览器侧每组件一格开关（D17）。
  **"多包"买到的是"每包一个客户端 graph row"，不是"每组件一个开关"** —— 组件行仍只跟随宿主行的启停。
  **机制前置**（手册 §4 逐条取证）：安装语义只支持「主包 patch 引用子包」
  （`installBundle` 要求这次 `pnpm add` 恰好新增 1 个直接依赖 ⇒ 子包**不得**各自成为被单独安装的 bundle）；
  `workspace:` / `bundledDependencies` / monorepo **不被支持** ⇒ **同仓开发、各自发布**；
  发布纪律 = 主包以**精确版本**依赖子包 + 子包名**单一出现点**。
  **目录落点**（手册 §8.1）：同仓 `packages/<pkg>/`，不用 workspace 协议。
- **D9 不推翻 [ADR-0003](./0003-build-time-module-inlining.md)**：浏览器半边继续靠**构建期内联**
  （不改用运行时模块系统）；**多包后是"每包一个产物"**（手册 §7.2 的构建改造），客户端懒加载 / 分块
  仍不在范围内（见 D16）。
- **D10 组件元数据按宿主契约写**：`exports` 三连（`./<c>`、`./<c>/package.json`、`./<c>/locale/*.json`）；
  `locale/` 目录**只放语言名文件**（否则整行元数据丢、显示裸 specifier）；**每个组件各带一份同目录图标**；
  **不写 `dsh-plugin.json`**（运行时零消费者），将来若要上架市场再补。
- **D11 兼容与数据安全**：保留旧行 id（老用户 profile 的 patch 里已有它）；`files` 是**逐文件**白名单
  ⇒ 新增文件逐条登记；覆盖既有行时必须给**完整** `config`（覆盖是整体替换、不深合并，否则迁移标记会丢、
  迁移会重跑）；每行独立迁移标记，新增组件必须同步其名单；**先校验后迁移**。

### C. 边界与契约（锚定 / 解耦的落地动作）

- **D12 「收紧契约」是待完成的部分**（判据 = **M8** 边界的可声明率、**M9** 跨模块隐式共享面）：
  **①** 组件注入面收窄 —— 组件不再解构整个内核对象，改为消费**显式列出的键**，且每一键都必须落在内核的
  **公开面**；**②** 每个 `lib/routes/*.js` 带一份**显式声明键集**（单一真源），与门面调用点**双向对账**
  （"声明了没人给"与"给了没声明"都要红）；**③** 内核**内部面**不得被组件 / 路由族直接解构。
- **D13 内核的对外面分两级**：**稳定面**（被 ≥2 个路由族或门面共享基座消费的字段）＋
  **具名视图面**（内核为某个消费者 / 组件**显式声明、写进契约、可机械对账**的子集，带棘轮、缺键即抛）；
  两者合称**内核公开面**，**内部面** = 未出现在任一公开面里的字段。
  **视图面不得成为"把内部面洗成公开面"的暗门**：来自内部面的键必须在文档与阶段报告里**逐条列出**；
  视图面暴露内部面键是**有意保留的耦合**，不为"看起来干净"把键搬进稳定面。
  **稳定面仍可按原定义扩**（只有当某键确实被 ≥2 族共享时才升）。
- **D14 「把实现代码搬进包」是待完成的部分**（判据 = **M10** 实现归属唯一性）：
  组件自己的路由实现随组件走（`lib/components/<c>/`；**P-F 2026-10-16 起三格统一到 `packages/<pkg>/lib/`**），主包**不留**它的注册点；
  归属搬移**不是行为改动** ⇒ 路由账的条数与路径集合必须逐条不变。
- **D15 取服务的姿势**：组件行与主行同款 —— 先声明 `export const inject = ['webServer']`，再直接读 `ctx.webServer`；
  **不许**在没有 inject 声明时直读服务属性（cordis 的 reflect `get` 会当场抛，早退分支变成死代码）。
  teardown 必须交给 fiber（`ctx.effect`）而不是只 `return`：`export function apply` 有 `prototype`
  ⇒ cordis 走 `new` 分支、返回值被丢弃 ⇒ 卸载不撤路由、再装载撞 duplicate。
- **D20 配置项的归属 = 代码归属，不是状态归属**（**2026-10-16 用户口径**；落地手册 §6.1 / D-6）：
  **键与状态全部留主包唯一内核** —— `lib/settings-schema.js` 的键面、消毒、`selection` / `setSetting` /
  `emit` / 持久化一个都不动，键名与簇名不改（⇒ **零存档迁移**）；**随包走的是"画这一节"的渲染器
  与描述符**，落子包的浏览器半边（`packages/<pkg>/src/**`）；子包**不持有键、不另行持久化、不注册
  自己的 `settings.section`**；**代码注释必须明文重述本条**（真源在主包，本包只提供渲染器 / 描述符）。
  理由：在 D2 的口径下"键归谁"本身不是改善项，而状态分家会拆掉 M4=0 的单写者不变量与存档兼容。
- **D21 面板结构与包结构解耦**（**2026-10-16 用户口径**；落地手册 §6.3 / D-7）：
  **设置分区表与分区对账口径暂维持现状**（不重画 ⇒ 零存档迁移；判据复算见
  `test/verify-settings-namespaces.mjs`）；面板怎么分簇 / 分节按**信息架构**定，**不按包边界推导**
  —— 拆包不产生分区重画，分区也不构成拆包边界；将来真要重画是**独立一件事**
  （改分区表与口径 + 老存档语义映射），与本轮拆包解耦。
- **D22 主包停用时的族级语义：不自动撤子包行**（**2026-10-16 裁决**；手册 §6.5 / D-13 的残余开口）：
  子包宿主半边都声明 `inject: ['wallpaperEngineHost']` ⇒ 主包行一关、provider 不在 ⇒ 子包 fiber 按
  `inject` **级联 park**（`apply` 不跑、路由不注册），所以"主包已关、子包路由还在"的**半死状态在机制上
  不成立**，也就不需要"随主包行一并撤走子包行"这种越界动作（它要主包运行时增删 profile 行，撞手册
  §2.4 的粒度事实与 `I8`）；"整族已停用"由**主包行的状态面**渲染（复用 D3③），子包行显示
  "因主包停用而搁置"，**不新增**跨包提示通道。

### D. 明确不做（免得反复讨论）

- **D16 不做浏览器侧「关掉即不下载」的包内懒块**：它改善的是**下载粒度**，对 M1–M10 **一项都不改善**
  ⇒ 不进待办。机制事实（`require.async` / `client.<name>.js` / 上游先例 / `files` 逐条登记 /
  「未启用」与「启用但失败」必须可区分）与重立项触发线在第 5 条事实与 §触发线里存着。
- **D17 不做浏览器侧每组件一格开关**：客户端 graph row 是**包级**的（事实 3）⇒ 多包最多给到**包级**开关，
  给不出"组件行一格"；且那属于 D16 已排除的下载 / 分块粒度。客户端只**跟随**宿主行的启停。
  （原句的理由"而 D8 不做多包"已随 D8 改写失效，**本条结论不变**。）
- **D18 `dsh-plugin.json` 不写**（运行时零消费者）；将来要上架市场再补。
- **D19 边界漏口单独处理**：`lib/routes/presets.js` 与立绘 / 头像落盘路径的耦合（事实 12）
  **不在开关语义范围内**，另立一项（它属"锚定边界"，走 D2 的度量）。

## Consequences

**收益**

- 复杂度按可复算的指标下降：门面从巨石变成"装配 + 协议聚合"，每个功能族有**唯一落点**。
- 宿主侧获得**每个组件的显示元数据与独立开关**（插件管理器里是 N 行，而不是一行黑白开关），
  且关掉之后**界面与配置项一起消失**（D3）—— 用户不必再看"下载了却坏掉的半套功能"。
- 边界从**注册点**落到**文件归属 + 可声明、可对账的键集**（D12–D14）：谁依赖谁一眼可查。
- 「加一个功能」有唯一答案（新组件目录 / 新注册表项），不必先读完整门面。

**代价 / 我们放弃了什么**

- **放弃了「只靠包结构就能解释开关」**：D3 之后读代码的人必须知道"行的可见面在哪里声明"，
  而这份声明跨宿主与浏览器两侧。
- **放弃了"浏览器半边与宿主行状态零耦合"**：可见性契约必然多一个宿主只读面。
  缓解 = D3② 的单一真源 + D3③ 的"读不到按可用渲染"（新耦合不得成为新的静默失效源）。
- **放弃了"公开面 = 稳定面"这种单层级简洁性**（D13 有两级公开面）。
- **放弃了"关掉组件行 ⇒ 浏览器侧不下载"**（D16）：本轮的目标是边界与契约，不是下载粒度。
- **放弃了一部分"重构过程指标优先"的纯粹性**（D3）：界面级开关本身不改善 M1–M10，
  这是用户点名的成品语义优先。
- **P2-7 类的契约收紧会改行为**：漏声明一键从 `undefined` 静默通过变成响亮报错
  ⇒ 顺序必须是**先加判据、再收窄**（反了就没有安全网）。
- **搬家会让部分守卫静默失去覆盖**：守卫按路径钉死，被读文件一搬家可能整条崩
  ⇒ 搬家与守卫改造**同一次提交**，并先证明"牙还在"（负对照）。
- 包体积随组件数增长（每个组件各带一份图标，且图标不能共享）。
- 上游同时演进时的冲突面（缓解：先纯搬移、面窄、每步独立提交可单独 revert）。

### 验收（每阶段通用，命令见 [`BUNDLE-SPLIT.md`](../wip/BUNDLE-SPLIT.md) **附录 C**）

1. `npm run verify:all` 全绿；`lib/client.js` 除本阶段有意的改动外**逐字节不变**。
2. **M8**：路由族 / 组件入口的声明面与实现面**逐键相等**（目标 100%）；**M9**：跨模块隐式共享面**归零**；
   **M10**：实现归属唯一（`lib/routes/` 零残留）。
3. **D3 的可见面判据**：每行一个负对照（关掉 ⇒ 该行声明的每个可见面落点都不渲染），
   同一判据在"行在"时判绿；反向对账（gate 了没声明 / 声明了没 gate 都红）；
   状态面失效 ⇒ 按可用渲染（正对照）；`components.failed` 非空必须有可区分形态。
4. **生效时机可见**：`cordis.patch.yml` 改动需重启/重载这一条，必须写进面向用户的文档。

## 重新考虑的触发线

1. **首屏 / 包体量成为用户侧首要抱怨，且代码分割成为必需** ⇒ 触发 [ADR-0003](./0003-build-time-module-inlining.md)
   写下的代码分割线，并重议 D16（包内懒块）。
2. **宿主开始支持子路径行各自的客户端半边**（组件级 `dsh.client`）⇒ D17 的前提消失，
   须重写一份 ADR 说明新形态。
3. ~~**某个组件需要独立发布节奏或独立版本号** ⇒ 单包多行做不到，须重议 D8 与发布面。~~
   **已触发并落地（2026-10-14）：D8 改写为「多包」** —— 但**"独立发布"仍不是目标**：子包版本一致，
   发布面仍是主包一个名字。
4. **设置分区被证明不可行或代价过高** ⇒ D7 的前提动摇，组件化的落地方式必须重议（而不是绕过它）。
5. **"改口链"再次成为阅读负担**（本页被迫再次加修订层、或决定编号与实际语义不符）⇒ 回来做一次
   与本次同款的**合并重写 + 旧件归档**，而不是继续叠 Amended/Superseded。
6. **D3③ 在实践中造成"关掉了却还显示"** ⇒ 说明行状态面不可靠，重议 D3② 的承载面
   （例如改为构建期 / 装载期的确定性注入）。
7. **`kind: 'const'` 的设置键与组件行的归属无法自洽**（键恒为常开，而其功能由某个可关的行提供）
   ⇒ 重议 D3① 的边界，必要时把该组件的可见面收窄到"仅隐藏控件、不隐藏运行时行为"。
