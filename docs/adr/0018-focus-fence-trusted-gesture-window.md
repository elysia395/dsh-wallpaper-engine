# ADR-0018: 元素级焦点围栏按「可信手势窗口」放行，不做一刀切

- **Date**: 2026-11-02
- **Status**: Accepted
- **Deciders**: Y1X1n（起草）；沿用 #148 / #169 维护者已定的方向
- **Related**: #148（网页壁纸周期性抢焦点）、#169（§3 残留收口）
- **Source of truth**: `lib/we-focus-guard.js` 的文件头注释（机制与射程）、
  `src/focus-handback.js` 的文件头注释（宿主半的三条判据）、
  `test/verify-scene-live.mjs`（围栏判据）、`test/verify-client.mjs` 的 A3-F 段（交还判据）

## Context

网页 / 场景壁纸里的作者脚本会在**捕获相**里调 `window.focus()`，也会用定时器反复调
`element.focus()`，把键盘焦点从 DSH 的输入框、下拉框、账号菜单手里拿走。用户在打字、
输入法候选到一半时会直接断掉。

围栏天然分两层：

1. **帧级**（整个壁纸 `window` 拿焦点）：可以无条件吞掉 —— 本插件从不把键盘送进壁纸帧，
   壁纸拿到帧级焦点在 DSH 里毫无用处，只会从宿主手里拿走键盘。
2. **元素级**（壁纸文档内某个元素拿焦点）：**不能**无条件吞掉。用户真去点壁纸时，
   壁纸自带的编辑框 / 模态框靠这次点击拿焦点是正当行为；一刀切会让这类交互永久失效。

同时，元素级的"最近一次真实交互"判定本身有个可被伪造的入口：如果只看事件类型 + capture 相，
壁纸文档里一次 `dispatchEvent(new PointerEvent('pointerdown'))` 就能打开放行窗口，
随后再夺焦 —— 既放行了本该拦的行为，也让自证读数自相矛盾。

## Decision

**帧级无条件吞；元素级按「可信手势窗口」放行。**

- **D1 — 帧级一刀切。** 壁纸 `window` 的 `focus()` 无条件吞掉，只记计数。理由见 Context 第 1 条：
  它在本插件里没有正当用途。
- **D2 — 元素级留窗口，但窗口只由可信来源打开。** 只认两种来源：
  ① 事件 `isTrusted === true`（用户真手在壁纸文档里的原生事件）；
  ② 宿主 shim 的注入通道期间（围栏晚于 shim 注入，故可包裹该通道函数，在注入期识别）。
  其余（壁纸文档自派的事件）**不刷新窗口**，单独记账，不参与放行判定。
- **D3 — 窗口外吞掉并留证据。** 吞掉时记时间戳与调用栈头，壁纸帧控制台可自证"谁在夺焦"。
  逃生门（统一放开两条围栏）保留给对比测试，不作为用户开关。
- **D4 — 两族原型都要守。** `HTMLElement` 与 `SVGElement` 的 `focus` 是两套独立原型上的两处，
  只包一族会漏掉另一族；两族共用同一条围栏与同一套调用计数，装没装上分别如实记账。
- **D5 — 围栏只负责"别让壁纸成为主动作恶的一方"。** 不经过 `focus()` 的路径（`autofocus`、
  模态框、`label` 转发）与跨源窗口代理的 `top.focus()` 由**宿主半**兜底：把焦点交还给用户
  本来在用的元素。两侧的手势窗口取同一口径。
- **D6 — 宿主侧「焦点被腾到 body」那一族先只记账。** 它不经过 `focus()`（围栏够不着），
  也不是"落进壁纸帧"（交还没有目标），因此只把落点次数与时间戳记进自证面，
  与真正的交还计数分开，避免两类成因在读数上混为一谈。是否补偿由真机样本决定。

## Consequences

**收益**

- 用户点壁纸时作者页的编辑框、模态框照常可用；无手势的周期性夺焦被拦住。
- 自派手势无法再伪造"用户点了壁纸"，放行窗口的来源可解释。
- 读数可分辨：拦了多少次、放行了多少次、被拒的自派手势多少次、宿主侧把焦点腾掉多少次。

**代价**

- 壁纸文档若依赖"自己 dispatch 假事件来给自己拿焦点"，该用法会被吞掉。这是有意的收窄：
  无手势的程序化夺焦本就在围栏射程内，被拒次数可核。
- 用户真点壁纸后的一段窗口内，作者页仍可借这次点击拿焦点。这是设计取舍（用户确实点了壁纸），
  不是漏洞。
- 跨源窗口代理与不经过 `focus()` 的路径必须靠宿主半兜底，两侧判据要一起看才完整。

## 重新考虑的触发线

- 真机样本显示"可信来源"判定把合法交互误伤成被拦（例如某些 shim 注入形态无法被识别），
  ⇒ 先补来源识别，而不是放宽到"只看事件类型"。
- 宿主侧「焦点被腾到 body」的真机样本积累到能区分成因 ⇒ 再决定要不要补偿，并按 D6 把
  补偿与交还的读数分开。
- 围栏射程内出现新的夺焦路径（新的 API / 新的原型） ⇒ 扩围栏并补判据，不改成"全放行"。
