## 1. 目标 / 非目标

**目标**（一句话：**一名一物、一把刻度一条曲线**）

1. **同名不同物 → 一名一物**：把"名字不构成区分"的几对拆开（最典型：`雾化` 与 `壁纸模糊` 量程同为
   0–60px，一个喂 `backdrop-filter`、一个喂 `filter`）。
2. **同名不同手感 → 曲线/刻度归一**：同一名词（"透明度"）在不同面走同一形状的曲线；量程已由追版的
   R4 统一过一把，本次只动**曲线**。
3. **状态词与对象缺失 → 补上**：需要靠 hover 提示才分得清的两个"帧率"、以及"亮度只作用壁纸层"这类
   **同名不同作用域**。

**非目标**（明确不做，免得范围失控）

- 不动玻璃**架构**（两态模型、门控策略、D4 分档已由 #140 落定，见 `adr/0008`）。
- **不改设置键名**：本仓的取舍是"复用既有键、不新建平行键"（出处：代码侧按 `D2` 标注 —— 先例：`chatGlassFidelity` 被「对话框玻璃·独立配置」复用）。收拢只动**标签文案 / 曲线常量 / tooltip**，键名与存储形态不动 ⇒ 迁移面为零。
- 不引入第二套"全局 / 跟随"机制 —— 那是 §2 的 ⑤，单独立项。

## 2. 分期与取舍

### 第一批（低风险：文案 + 一条曲线；建议合成一个 PR）

| # | 内容 | 落点 | 风险 |
|---|---|---|---|
| ① | **「雾化」→「玻璃模糊」** 命名成族（与「壁纸模糊」「侧栏模糊」对齐成"对象 + 模糊"） | `lib/settings-schema.js` 的 label / `src/glass-panel.js` 的行标签 / `src/i18n-copy.js` 英文词表 / 判据里按**标签字面量**找滑杆的地方 / `test/fixtures/harness-ui-surfaces.json`（棘轮夹具）/ README 三份 + `docs/**`（**不含归档区** —— 归档账本里的旧名保持原样） | 纯文案；但**必须一次原子改完**（判据按标签查找，漏一处即红） |
| ② | **透明度曲线归一**：侧栏族与内容面各自的曲线对齐全局那条 | `src/glass.js` 的取值曲线 | **行为改动**：观感会变 ⇒ 需金线夹具重录 + 真机对照；不能混进"纯文案"的批次里蒙过去 |
| ④ | **两个"帧率"改名区分对象**：「帧率上限」（视频解码抽帧转码）vs「实时渲染帧率」（WebGL 渲染 fps） | schema label + i18n + 判据标签 + 文档 | 纯文案 |

### 不做（改为"提示互指"）

**③ 亮度 + 暗化合并**：两者不是同一数学物（`filter: brightness()` 是乘法，`scrim` 是加一层黑遮罩且会
压对比度），合并成一轴会**丢一个自由度**；而且要动 schema 键 + 迁移 + 金线 + 判据，收益不抵成本。
⇒ 只在两条 tooltip 里互相指明差异与取舍（"亮 = 压暗画面本身；暗化 = 画面与文字之间加一层黑"）。

### 单独立项

**⑤ 统一跟随机制**：把侧栏族的 `sidebarFollowGlobal` 并进 `glassMode`（本仓已有合并先例：曾经
「对话栏玻璃保真度」与「对话框玻璃·保真度」两个旋钮控一件事，后撤并成一个）。

- 顺序理由：⑤ 应当在 **#140 的 D4/占位器/`glassMode` 架构**上做（"哪些面在哪一档、谁读自己的值、
  门控与占位器如何配对"已被判据钉住）⇒ 先落地 #140 显著降低 ⑤ 的成本。
- **范围要含新语义**：上游新加了**皮肤中心（dsh-skins）互操作** —— 皮肤上台 ⇒ 我方壁纸与玻璃**整族让路**
  （+ 让路记忆落盘）。"让路"与"跟随/独立"同属"**谁的值生效**"这一家族，⑤ 必须把它一起纳入，
  否则会做出第二套平行机制（正是 ⑤ 要消灭的东西）。

## 3. 每批的落地判据与闸门

照本仓纪律（判据跟着代码走、每条判据带负对照、能写在代码旁的规则不单写文档）：

- **① / ④（文案）**：判据里按标签查找的调用点必须同步；新增一条**反向判据**"旧名不得再出现在任何
  面板标签里"（正负对照：把 label 改回旧名即判红）。`test/fixtures/harness-ui-surfaces.json` 是
  **棘轮夹具**，改名即需同步，否则 compat 腿会红。
- **②（曲线）**：这是**行为改动** ⇒ 三件套：① `test/fixtures/settings-sanitize-golden.json` 按既有
  安全阀脚本重录（只允许预期键漂移）；② 断言"同一透明度档位在两侧栏与全局得到同一 alpha"（带负对照）；
  ③ **真机对照**（曲线是观感，源码级判据只能守形状、守不住"看起来是否一致"）。
- **全批**：`npm run verify:all`（含 build 重建 `lib/client.js`、`verify:docs`、`smoke`）+ 真机重启复核。
  备注：`verify-system-fonts` 的"真子进程多字节解码"一条已带**环境跳过档**（受限沙箱禁管道
  spawn 报 `EPERM`/`EACCES` 时明示跳过、不算过也不判红；正常环境照常真跑），不再需要"以真 CI 为准"的口径。
