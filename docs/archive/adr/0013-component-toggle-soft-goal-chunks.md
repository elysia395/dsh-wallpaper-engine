# ADR-0013: 「组件可独立开关」重判为软目标，用包内懒块实现「关掉即不加载」（component toggling revisited: soft goal, via package-local client chunks）

- **Date**: 2026-10-14
- **Status**: Superseded by [ADR-0014](./0014-goal-reanchor-and-contract-tightening.md) —— **仅就其目标档位**（撤销"关掉即不下载"的目标身份，转为非目标 N5）；本 ADR 的**机制事实与重立项触发线保留**，正文不改写
- **Deciders**: 用户（产品口径）+ 实现（本仓）
- **Amends**: [ADR-0012](./0012-bundle-multi-component-rows.md)（D1 的口径「可开关本身不加分」与 D4 的前提「浏览器侧独立开关不是需求」）
- **Related**: [ADR-0003](../adr/)（浏览器半边靠构建期内联 —— 本次触发它的「代码分割」触发线，且**不**推翻它）、
  [ADR-0002](../adr/)（设置的单一真源）
- **实施计划**: [`docs/wip/BUNDLE-SPLIT.md`](../) 的 §6 与 §8「P3′（可选格）」

## Context

### 口径变更（本决策的动机）

- 2026-10-13 的口径是：「『浏览器侧组件能单独关』本身不是一个需求，更像一个结果，拆包的核心目标是降复杂度」
  ⇒ ADR-0012 据此把「可独立开关」降级为**可能的结果**，并写下 D4「不做多包」。
- 2026-10-14 用户改口：**「由于会有用户注重测试关闭子插件，「浏览器侧可独立开关」现在被重判断为『最好可以』」**。
  动机是**测试场景**：用户为排查问题关掉一个子插件时，不想在浏览器侧看到／加载它的残留。

### 可测事实（符号名 / 文件路径作锚点，不写行号与数值）

1. **宿主客户端加载器原生支持「包内懒块」**：模块工厂拿到的 `require` 上挂着 `require.async(spec)`
   （`dsh-client-modules` 的 `makeRequire()` / `importChunk()`）——
   相对说明符必须以 `client.` 开头且文件名为 `client.<name>.js` 形态（`CLIENT_CHUNK` 校验），
   由 `chunkId(ownerId, fileName)` 定身份、按需走 `importChunk()`；懒块自己的注册走
   `window.__ModuleLoader__.load({ id, factory, chunk })`（`chunk` 字段同样受 `CLIENT_CHUNK` 校验）。
2. **宿主侧按需出块、不需要清单变更**：`chunkRequest()` 在**当前 revision** 的包里匹配
   `/plugins/<包名>/<fileName>`，`chunkResponse()` 从 `dirname(包内客户端入口)` 出文件
   （文件不存在即 404 ⇒ **必须在安装树里、即逐条登记进 `files`**），响应带不可变缓存头。
   即：块的可用性只取决于「包的客户端入口所在目录里有这个文件」，不取决于 patch 行、不取决于新的清单字段。
3. **上游同版本已有先例**：`dsh-client-ui-sidebar-terminal` 的 `client.terminal.js` 与
   `dsh-client-ui-sidebar-documentpreview` 的 `client.pdf.js` / `client.excel.js`，都以
   `react.lazy(async () => (await require.async('./client.<x>.js')).<Export>)` 形态按需装载；
   两个包的 `files` 里都写着 `lib/client.*.js`。⇒ 这不是我们要发明的机制，是**照抄宿主惯例**。
4. **客户端 graph row 的粒度仍然是包名**：`dsh-client-modules` 用 `exactPackageSpecifier()` 只认裸包名
   （或恰好两段的 scope 名），再 `nearestPackage()` 向上找清单，最后 `table.set(packageName, …)`。
   ⇒ 懒块改变的是**下载粒度**，**不是**开关粒度。
5. **我们的主行仍是构建期内联**：`scripts/build-client.mjs` 按 `INLINE_MODULES` 把 `src/**` 剥掉 `export`
   注入 `lib/client.js` 的同一工厂作用域（ADR-0003）；懒块是**附加产物**，不改这条管道。
6. **组件装载状态已有真源**：`/wallpaper-engine/diag-log` 的 `components`
   （`declared` / `loaded` / `started` / `failed` / `missing`，P2-4 落地、P2-5C 补齐三态账本）
   ⇒ 客户端不必靠「试着加载，失败再降级」猜组件是否可用。

### 概念澄清（本 ADR 存在的理由）

"浏览器侧可独立开关"混着两件事，之前被当成一件：

| | 含义 | 今天能做到吗 |
|---|---|---|
| **开关粒度** | 谁提供一个开关：宿主**行级** / 客户端**每组件一格** | 宿主行级 ✅（P2 已落地，插件管理器里每组件一行）；客户端行级 ❌（`exactPackageSpecifier()` 只认包名） |
| **加载粒度** | 关掉之后，浏览器侧还下载 / 渲染不渲染这个组件的代码 | 之前 ❌（单包内联 ⇒ 全量随主行下发）；**现在 ✅（包内懒块）** |

## Decision

- **D1 —— 「浏览器侧可独立开关」从"不是需求"重判为软目标（最好可以）。**
  它**仍然不是**验收条件：主线的好坏继续只按 [`BUNDLE-SPLIT.md`](../) §3 的度量衡量。
  但它也不再被"可开关本身不加分"排除 —— 它是**独立的能力目标**，排在主线收口之后（可选格，不阻塞 P2/P4）。
- **D2 —— 档位取"真独立加载"（关掉即不下载），不取"客户端各自开关"。**
  关掉组件行 ⇒ 浏览器侧**不请求**该组件的块、**不渲染**它的 UI；开关本身仍由**宿主行**提供。
  ADR-0012 的 D4（不做多包 monorepo）**维持不变**：客户端每组件一格开关，只有多包能给，而它不在本轮范围。
- **D3 —— 实现路线 = 包内懒块（方案 B′）。** 组件专属的客户端代码进 `lib/client.<c>.js`
  （与包内客户端入口同目录、文件名匹配宿主的块规则、`files` 逐条登记），客户端在**该组件启用**时
  才 `require.async('./client.<c>.js')`。
- **D4 —— 懒块不推翻 ADR-0003。** 主行的客户端半边继续构建期内联；懒块只把**组件专属**的代码
  从主产物搬到块里。ADR-0003 的正文保持原样，本次只触发它写下的「代码分割」触发线。
- **D5 —— 关闭后的行为必须确定：以宿主账本为唯一真源。** 客户端据 `components` 的 `started` / `failed` /
  `missing` 决定是否装载块，**不许**用"尝试加载失败再降级"代替；「未启用」与「启用但失败」必须可区分
  （与 P2-5C 的真机教训同源：静默降级与假绿比响亮报错更坏）。
- **D6 —— 软目标不得让任何复杂度度量回退。** G5 的实现若让 M1–M7 任一项变差（例如块让最大文件
  或生成物机械面变大），按度量优先处理，或如实降档（见触发线）。
- **D7 —— 升到客户端行级开关要新的买方理由。** 首屏体量、独立发布、或"客户端各类开关"成为正式需求时，
  按 ADR-0012 的触发线**另写** ADR 重议多包；不改写 ADR-0003 与本 ADR 的正文。

## Consequences

**收益**

- 测试场景可以**干净关闭**：关掉一个组件行，浏览器侧真的不下载、不渲染它的代码 —— 而不是"下载了再隐藏"。
- 主产物不再随组件数线性增长（组件专属代码按块下沉），且兑现这一点**不需要**多包：发布面不翻倍，
  不必踩在宿主声明"可能无预警变更"的 `dsh.client.*` 上。
- 顺手把"关掉后界面还剩半套功能"这个被测出来的真实痛点，变成有真源、可判据的行为。

**代价 / 我们放弃了什么**

- **放弃了"客户端每组件一格开关"**。关掉组件行仍然只关宿主半边；浏览器侧的开关仍来自宿主行，
  客户端只跟随。要改变这一点只有多包一条路（D7）。
- **引入异步装载**：块的到达晚于主行 ⇒ 组件 UI 的首帧需要占位/无闪动约束，装载失败必须可见
  （不能变成"这功能莫名不见了"）。
- **构建与守卫面扩大**：构建脚本要出块；`files` 要逐条登记块文件；需要新增"块 ↔ 组件归属"这类判据
  （防止出现"没人 require 的孤儿块"与"组件目录里的代码没进任何块"两种静默漂移）。
- **缓存与热更面要单独证明**：块的响应带不可变缓存头、身份含 revision ⇒ 重建 / HMR 后旧块不能残留。

## 重新考虑的触发线

1. **客户端行级开关成为正式需求**，或出现只有多包能解的问题（独立版本、独立发布节奏）⇒ 按 ADR-0012 的
   触发线另写 ADR 重议方案 C，并说明为什么值得付发布面 ×N 与 `dsh.client.*` 的变更风险。
2. **懒块的缓存 / 热更面被证明不可控**（重建后旧块残留、或块与主行 revision 不一致）⇒ 如实降回
   「联动隐藏」档，并在实施计划里写明降档理由，而不是假装仍然独立。
3. **首屏 / 包体量成为用户侧首要抱怨** ⇒ 触发 ADR-0003 写下的代码分割线（与本 ADR 同一实现面、不同目标）。
4. **宿主开始支持子路径行各自的客户端半边**（组件级 `dsh.client`）⇒ D2 的前提（懒块是唯一低成本出路）消失，
   需要重写一份 ADR 说明新形态（ADR-0012 的触发线 2 同款）。
