# ADR-0016: 组件行开关的语义从「路由级」升为「界面级」（component row toggle: from route-scoped to UI-scoped）（草案）

- **Date**: 2026-10-14（提案）
- **Status**: **Proposed** —— 待用户评审；评审通过后改 `Accepted` 并补 `Amends` 的落地状态
- **Deciders**: 用户（产品口径）+ 实现（本仓）
- **Amends**: [ADR-0014](./0014-goal-reanchor-and-contract-tightening.md) —— **仅 D2 的作用域**：
  由「A 语义 = 宿主行级开关，**不含**浏览器侧可见面」扩为「A 语义 = 宿主路由 **＋** 该组件的浏览器可见面」，
  并**撤销** D2 里"明确不含"那句结论。ADR-0014 的 D1 / D3 / D4 / D5 及其三件核心目标**不变**。
- **Related**: [ADR-0012](./0012-bundle-multi-component-rows.md)（一 bundle 多组件行）、
  [ADR-0013](./0013-component-toggle-soft-goal-chunks.md)（「关掉即不下载」的机制事实 —— 本 ADR **不**重开它）、
  [ADR-0003](../adr/)（浏览器半边靠构建期内联）、
  [ADR-0015](./0015-component-view-face.md)（内核公开面 = 稳定面 ∪ 具名视图面）
- **取证报告**: [`docs/archive/wip/COMPONENT-TOGGLE-REPORT.md`](../)（逐条现象 + 机制 + 复算命令）
- **实施计划**: [`docs/wip/BUNDLE-SPLIT.md`](../)（本 ADR 通过后新增阶段；目前尚**未**列入）

## Context

### 触发这件事的用户口径

- 用户实测「关闭 `mascot-avatar` 行」后发现：**关闭瞬间毫无变化**（要重启才生效）、
  重启后**区别只是吉祥物图标破图**，而立绘 / 头像的**上传入口与设置项照旧可见**。
- 用户对目标形态的期望（2026-10-14 重新给定）：**关掉一行 ⇒ 该组件对应的界面不显示、配置项不可见**。
- 用户同时对优先级给了明确口径：**"实际效果和最终成品低复杂度低耦合优先于重构过程中的复杂度"**
  —— 即：为了成品语义正确，**允许推翻此前的 ADR 与部分测试体系**。

### 可测事实（符号名 / 文件路径作锚点，不写行号与数值）

1. **A 语义的实际作用域 = 宿主路由注册**。组件入口 `lib/components/<c>/index.js` 的 `applyImpl()`
   里只有 `webServer.register(...)` 一族动作；关掉行 ⇒ 该组件路由整族不注册。
   真实故障形态与"关掉"在客户端**长得一样**（都是 404），
   这一点被 `lib/index.js` 的组件装载探针注释自己点明：客户端「看」是静默坏
   —— `src/client.js` 的 `<img src>`、`src/avatar-layer.js` 的 `<img>` 没有 onerror。
2. **浏览器半边是包级的**（ADR-0012 Context 的事实不变）：`dsh-client-modules` 的
   `exactPackageSpecifier()` → `nearestPackage()` → `table.set(packageName, …)`
   ⇒ 一个包只有一个客户端 graph row；子路径行**完全不参与** `dsh.client` 扫描。
   ⇒ 组件行**不可能**有自己的客户端开关；本 ADR 也不打算做每组件一格开关。
3. **客户端零状态面**：`src/**` 里没有任何地方读组件装载态（`components` / `componentProbe` 零命中）；
   `/inventory` 不返回组件态；装载账本只经 `/diag-log` 的 `components` 字段对**排障者**可见
   （`lib/host-boot.js` 的三本账 + `lib/routes/diag.js`）。
4. **`cordis.patch.yml` 的生效时机是重启/重载**：该文件住在包目录，不在 `dsh-hmr` 的监听面
   （监听面 = profile 的 `package.json` / `cordis.patch.yml` 与 `$DSH_HOME/cordis.patch.yml`）。
   ⇒ "行开关"天生**不是运行时热切换**，本 ADR 必须把这条写进语义（否则用户永远会觉得"没生效"）。
5. **组件行与可见面现在是靠文档对齐的**：`mascot-avatar` 的可见面散在 `src/panel-tabs.js`
   （`renderMascotTab`、扩展页签的 `AVATAR_EXTENSION_MODULE`）与 `src/avatar-layer.js`；
   `about-notice` 的可见面在「关于」页签的 star 行与两张二维码；`media-bridge` 的可见面在
   `adapterTarget` 控件与媒体轮询段。**没有任何机械判据**把这些落点与组件行绑起来。
6. **宿主侧另有一条边界漏口**（与开关语义正交，见 `COMPONENT-TOGGLE-REPORT.md` §5）：
   `lib/routes/presets.js` 的 `DEPS` 直接含 `mascotPath` / `mascotDir` / `avatarPath` / `avatarDir` /
   `AVATAR_SIDES`，所以关掉 `mascot-avatar` 行后预设族照样能读写这两族资产。

### 为什么这值得推翻一条既有结论

- 现行口径（ADR-0014 D5）：**"不改善 M1–M10 任何一项的工作一律不做"**。
  界面级开关**确实不改善任何一项度量** —— 若不改口径，实施者会在"这算哪门子收益"上无据可依，
  最后要么偷做、要么被守卫劝退。**要么明确不改，要么明确改口径；不能默认**。
- 用户已给出更高的优先序：**成品语义 > 重构过程指标**。本 ADR 就是把这个优先序写成可引用的决定，
  并把它约束在**可判据**的范围内（不是"为了好看"）。

## Decision

- **D1 行级开关的作用域升为「宿主路由 ＋ 浏览器可见面」**。关掉一个组件行 ⇒ ① 该行注册的 HTTP 路由不再存在
  （A 语义，不变）；② 该组件在浏览器侧声明的**可见面**（界面区块与设置控件）**不渲染**。
  **不含**：浏览器侧每组件一格开关（仍只有多包能给，仍不做，见 D6）。
- **D2 可见面必须由「行状态」派生，且清单双向对账**。浏览器侧不许手写"组件名 → UI"的映射表，
  必须由**宿主给出的行状态**驱动；每个组件行的可见面落在哪些渲染函数 / 设置键上，
  写成**单一真源**并由判据与实现**双向对账**（声明了没 gate、gate 了没声明，都要红）。
- **D3 失效口径（三条同时成立）**：
  1. **宁可显示、不可静默消失**：状态面读不到 / 请求失败 ⇒ **一律按"可用"渲染**
     （默认可见），与 `lib/kernel/component-session.js` 的"缺键即抛"是**不同场景的两条纪律**：
     内核缺键是**装错**（响亮报错），行状态读不到是**探测失败**（不许让用户的功能凭空消失）。
  2. **已声明的可见面缺失 ⇒ 明确的不可用形态**：`<img>` 一族必须有 onerror 兜底（回落内置默认 / 占位），
     禁止"破图 + 空值"；这条**不依赖 D1**，本身就是补既有缺陷。
  3. **失败必须可见**：装载失败（`components.failed`）与"未启用"在界面上**不能长得一样**，
     延续 ADR-0013 的 P2-5C 那课（"未启用"与"启用但失败"必须可区分）。
- **D4 状态面的契约是「只读、可缺失、单一真源」**：承载面候选 = `/inventory` 的只读字段（推荐，客户端已有单一出入口）
  或既有 `/diag-log` 的 `components`（现状是排障面）。选定后：
  **主机动态派生、客户端只读**；禁止在浏览器侧维护第二份组件名清单。
- **D5 A 语义是 B 的底座，不推翻**：路由仍照旧注册 / 撤掉；D1 只**增加**可见面这一层，
  不改变"关掉 ⇒ 路由消失"的既有行为与既有判据（`test/verify-bundle-rows.mjs` ⑧ 的真 cordis 往返全部保留）。
- **D6 明确不做（与本 ADR 一起钉死，避免反复讨论）**：
  - **不做**浏览器侧每组件一格开关（包级 graph row 的事实不变，只有多包能给，买方不存在）；
  - **不做**"关掉即不下载"（ADR-0013 的目标档位已被 ADR-0014 撤销；本 ADR 不重开它，机制事实仍住 0013）；
  - **不改** ADR-0003 的构建期内联（浏览器半边仍是包级单产物）。
- **D7 度量口径随之修正（**本 ADR 唯一的"推翻既有结论"处**）**：ADR-0014 D5 的
  "不改善 M1–M10 任何一项的工作一律不做"，在本条上让位于用户给定的优先序
  —— **"成品语义正确 + 低耦合"优先于"重构过程的指标收益"**。
  约束条件（防滥用）：本例外**只覆盖 D1–D3 定义的可见面工作**；
  其它任何工作仍按 ADR-0014 D5 判；且本 ADR 落地后必须新增**机械判据**（见 Consequences 的验收），
  不接受"做了但没人能验"。
- **D8 ADR-0014 只改 D2 的作用域**：其 `Status` 改为 `Amended by ADR-0016（仅 D2 作用域）`；
  正文不改写（历史保持原样）。ADR-0013 的正文与机制事实不动。
- **D9 边界漏口单独处理**：`lib/routes/presets.js` 与立绘 / 头像落盘路径的耦合（Context 事实 6）
  **不在本 ADR 范围内**，另行立项（它属"锚定边界"，与开关语义正交）。

## Consequences

**收益**

- 用户能得到的最终形态第一次被写清楚：**关掉哪一行 ⇒ 哪些界面与配置项消失**，
  且这件事有单一真源 + 双向对账 + 负对照，不靠文档散文对齐。
- "关掉 = 静默坏"这一条被从两种语义里同时消灭：D3② 让失败**看得见**，
  D1 让"关掉"与"坏了"在界面上**长得不一样**。
- 修正了一条口径漏洞：**验收"过程指标"不等于否定"成品语义"** —— 优先级由用户拍板，写进 ADR 而不是留在争论里。

**代价 / 我们放弃了什么**

- **放弃了"浏览器半边与宿主行状态零耦合"**：可见性契约必然让客户端多依赖一个宿主只读面。
  缓解 = D4 的"单一真源 + 只读 + 可缺失"，以及 D3① 的"读不到按可用渲染"（**新耦合不得成为新的静默失效源**）。
- **放弃了"只靠包结构就能解释开关"**：今后读代码的人必须知道"行的可见面在哪里声明"，
  而这份声明会跨宿主与浏览器两侧。
- **可能推翻此前把某些设置键定为 `kind: 'const'` 的结论**：`audioSource` / `mediaIntegration` /
  `mediaLyricsOnline`（`lib/settings-schema.js`）是"恒为常开"的键，而它们的功能确实由 `media-bridge` 提供
  ⇒ 升档后它们的"恒常开"就不再自洽。**这需要单独裁决**（本 ADR 只点名，不顺手改）。
- **测试体系要付改造费**：至少涉及 `test/verify-client.mjs` / `test/verify-scene-live.mjs`
  （面板契约）、`test/verify-inventory-index.mjs`（若扩 `/inventory`）、
  `test/verify-bundle-rows.mjs`（行 → 可见面映射的负对照）与生成物重算（`docs/ROUTE-INDEX.md` 等）。
  **用户已明确接受这一代价。**

### 落地的验收判据（必须先落判据、再改实现）

1. **每行一个负对照**：把某行关掉 ⇒ 该行声明的每个可见面落点**都不渲染**；
   同一份判据在"行在"时**必须判绿**（否则判据恒真）。
2. **反向对账**：某个可见面被 gate 了，但它的组件行没声明它 ⇒ 红；声明了却没人 gate ⇒ 也红。
3. **状态面失效口径**：状态面读不到 / 抛错 / 缺字段 ⇒ 界面**按可用渲染**（正对照），
   不许出现"探测失败 ⇒ 功能静默消失"（负对照）。
4. **失败可见**：`components.failed` 非空时界面必须给出**可区分的**提示形态（与"未启用"不同）。
5. **零行为回归**：四行全开时 `npm run verify:all` 仍全绿，且 `lib/client.js` 只在本阶段有意的改动处变化。
6. **生效时机可见**：`cordis.patch.yml` 改动需要重启/重载这一条，必须在**面向用户**的文档里写明
   （否则"改行后立刻看"永远被当成 bug）。

### 阶段拆分建议（写进实施计划时细化）

| 阶段 | 内容 | 是否依赖 D1 |
|---|---|---|
| S1 | 只读行状态面：宿主**动态派生**组件行状态并暴露；客户端能读到（不 gate 任何 UI） | 否（可先做） |
| S2 | 失效口径：`<img>` onerror 兜底 + "不可用形态" + 失败可见 | 否（**补既有缺陷，建议最先做**） |
| S3 | 可见面清单落成单一真源 + 双向对账判据 + 负对照 | 是 |
| S4 | 按清单 gate 三个组件行的 UI 与设置控件（含 `kind: 'const'` 三键的单独裁决） | 是 |
| S5 | 文档与生成物：可见面表进 `docs/CODE-STRUCTURE.md`；面向用户文档写明生效时机 | 是 |

## 重新考虑的触发线

1. **宿主开始支持子路径行各自的客户端半边（组件级 `dsh.client`）** ⇒ 与 ADR-0012 触发线 2 同款：
   「每组件一格开关」重新可行，回来重议 D6 第一条（届时另写 ADR）。
2. **可见性契约成为浏览器半边的第二个大耦合面**（客户端出现一堆"为了 gate 而传参"的管道）⇒ 回来重议 D2，
   考虑把可见面**下沉到组件自己的客户端模块**（即重启 ADR-0003 的代码分割线）。
3. **`kind: 'const'` 三键的裁决无法自洽**（保留恒常开 vs 随行消失两难）⇒ 回来重议 D1 的边界，
   必要时把 `media-bridge` 的可见面收窄到"仅隐藏控件、不隐藏运行时行为"。
4. **D3①（读不到按可用渲染）在实践中造成"关掉了却还显示"** ⇒ 说明状态面契约不可靠，
   回来重议 D4 的承载面（例如改为构建期/装载期的确定性注入）。
