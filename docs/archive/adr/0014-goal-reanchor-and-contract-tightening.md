## Context

### 口径变更（本决策的动机）

- **2026-10-13（ADR-0012）**：核心目标是**降低复杂度**；「浏览器侧组件能单独关」是**结果**而不是需求
  ⇒ D4 不做多包。同一天写下的判据口径是「**不改善度量任何一项的拆分，一律不做** —— 可开关本身不加分」。
- **2026-10-14（ADR-0013）**：用户改口「由于会有用户注重测试关闭子插件，「浏览器侧可独立开关」现在被
  重判断为『最好可以』」⇒ 把它升为**软目标**、拆成**开关粒度**（客户端每组件一格 = 只有多包能给 = 仍否）
  与**加载粒度**（关掉即不下载 = 包内懒块能给 = 接），阶段 = 可选格 **P3′**。
- **2026-10-14（本 ADR，用户重新给定目标）**：核心目标不是一件而是**三件并列** ——
  **降低复杂度**、**锚定模块边界**、**解耦合**；开关目标的语义是 **A 语义（宿主侧行级开关）**；
  并把**收紧契约**与**把实现代码搬进包**明确为**需要完成的部分**（不是"可选项"、也不是"副产品"）。
  ⇒ 这三条把前两份 ADR 的重心同时挪动了：ADR-0012 的目标面**变宽**（边界与解耦进核心），
  ADR-0013 的目标档位**被撤销**（下载粒度不是本轮的买方）。

### 可测事实（符号名 / 文件路径作锚点，不写行号与数值）

1. **门面是手工 DI 容器，键集只存在于调用点**：`lib/index.js` 的 `apply()` 里每个
   `registerXxxRoutes(webServer, { … })` 的键集就是那个族的**全部依赖面**；而 `lib/routes/*.js`
   文件头写的"契约"是散文，**没有判据对账** ⇒ 依赖面**不可声明、不可核对**。
2. **组件注入面名义上窄、实际上是整个内核**：`lib/kernel/host-kernel.js` 的 `createHostKernel()`
   返回一个**平坦对象**（文件头已把字段分成**稳定面 / 内部面**两级），但组件入口的 `applyImpl`
   是直接从**整个内核对象**解构的（`lib/components/*/index.js`）⇒ 门面/patch 行传的
   `{ hostKernel, base, pluginName, repoSlugFromPkg }` 没有收窄任何实际依赖。
   P2 的两件组件正是靠这个隐式面跑起来的。
3. **组件实现仍住在主包**：`lib/routes/about-qr.js` / `lib/routes/github-stars.js` 是 C8′ 的实现、
   `lib/routes/mascot.js` / `lib/routes/avatar.js` 是 C6 的实现 ⇒ 组件出户搬走的是**注册点**，
   "这个组件由哪些文件构成"目前只能靠文档说明，**位置本身不回答**。
4. **A 语义已经兑现，不是待建能力**：`cordis.patch.yml` 的同一个不带 `id` 的 `insert:` 里有
   裸包名行 + 两个组件行；行可被单独 `disabled`；两次真机故障（缺 `inject` 直读 `ctx.webServer`、
   以及 `export function apply` 的 `prototype` 让 cordis 走 `new` 分支、返回值被丢弃 ⇒ 卸载不撤路由）
   都已修，并被 `test/verify-bundle-rows.mjs` 的判据钉住。
5. **客户端 graph row 是包级的**（ADR-0012 Context 的事实不变）：`exactPackageSpecifier()` 只认裸包名
   （或恰好两段的 scope 名），`nearestPackage()` → `table.set(packageName, …)` ⇒
   **浏览器侧每组件一格开关只有多包能给**。
6. **包内懒块可用，但一项复杂度度量都不改善**：它改变的是**下载粒度**（ADR-0013 的事实 1 / 2 / 4），
   对"最大单文件体量、门面非装配占比、共享设置键数、守卫硬编码条数、归属唯一性"没有任何作用。

## Decision

- **D1 核心目标三件并列**：**降低复杂度**（门面与单文件体量、门面内非装配代码占比、
  「一个功能族 → 哪些文件」的唯一性）、**锚定模块边界**（落点唯一 **且** 边界**可声明、可核对**）、
  **解耦合**（模块之间只通过公开契约通讯：显式注入面 + 内核分级面，隐式共享清零）。
  三者互不替代：只有目录变了而没有可声明的边界，**不算锚定**。
- **D2 开关目标 = A 语义（宿主行级），且它是次级目标**：每组件一行的显示元数据、可被单独 `disabled`、
  **关掉再打开幂等无残留**。**明确不含**浏览器侧每组件一格开关（只有多包能给，仍不做）。
  **ADR-0013 的目标档位就此撤销**：「关掉即不下载」（包内懒块）**移出目标与待办**；
  其机制事实与重立项触发线保留在 0013 —— **不改写 0013 的正文**。
- **D3 「收紧契约」是待完成的部分（阶段 P2-7）**：① 组件注入面收窄 —— 组件不再解构整个内核对象，
  改为消费**显式列出的键**，且每一键都必须落在内核的**稳定面**；② 每个 `lib/routes/*.js` 带一份
  **显式声明键集**（单一真源），与门面调用点**双向对账**（"声明了没人给"与"给了没声明"都要红）；
  ③ 内核**内部面**不得被组件 / 路由族直接解构。判据 = 度量 **M8**（边界的可声明率）与 **M9**（跨模块隐式共享面）。
- **D4 「把实现代码搬进包」是待完成的部分（阶段 P2-8）**：组件自己的路由实现随组件走
  （`lib/components/<c>/`），主包**不留**它的注册点；**与第三个组件同批**做（为几个文件单独付一次
  守卫改造不划算）。判据 = 度量 **M10**（实现归属唯一性）**加上**"路由账逐条不变"（归属搬移，不是行为改动）。
- **D5 度量口径随之修正**：判据从"不改善 **M1–M7** 任何一项一律不做"扩为
  "**不改善 M1–M10 任何一项的工作一律不做**"；并写明 **「不改善度量」不等于「不做」** ——
  D3 / D4 是用户点名的**待完成部分**，它们改善的正是 M8–M10，因此不是可选项。
  **可开关本身仍不加分**：G5 是已兑现的形态，不构成新工作的理由。
- **D6 ADR-0012 的 D2–D7 维持不变**：单包多行、不做多包、不推翻 ADR-0003 的构建期内联、
  元数据按宿主契约写、保留旧行 id、`files` 逐条登记、覆盖既有行必须给完整 `config`。
- **D7 撤销一个目标不等于撤销一项能力**：包内懒块将来若因首屏体量或客户端行级开关重新立项，
  按 ADR-0013 的触发线**另写一份 ADR**；本 ADR 与 0013 的正文都不再改写。

## Consequences

**收益**

- 目标从一件变三件之后，「边界」与「解耦」有了**可判据的落点**（M8–M10），不再只是形容词 ——
  G1 与 G2 是同一件事的形状与内容，现在都能一键复算。
- 两个此前只有建议、没有买方的动作（**契约收紧** / **实现入包**）变成**有判据的待办**：
  它们不是为了"更好看"，而是 M8–M10 的唯一改善手段。
- 开关的档位**从此不再摇摆**：A 语义 = 宿主行级，已兑现；浏览器侧行级开关与"关掉即不下载"
  都明确落在目标之外，不再占用主线注意力。

**代价 / 我们放弃了什么**

- **放弃了"关掉组件行 ⇒ 浏览器侧不下载、不渲染"**（ADR-0013 曾接受它，代价是引入异步装载与
  构建/守卫面扩大）。理由：它**一项复杂度度量都不改善**，而本轮的目标是边界与契约。
  连带放弃的是它承诺的"主产物不随组件数线性增长"。
- **P2-7 会改行为** —— 这是它与 P0 / P2-1 / P2-2 的"纯搬移、零行为变化"最大的不同：
  漏声明一键从 `undefined` 静默通过，变成响亮报错。缓解是**先加判据、再收窄**（顺序反了就没有安全网）。
- **P2-8 会让 `lib/routes/` 不再等于"全部宿主路由"**：若干守卫按路径钉死，搬家可能让判据**静默失去覆盖**
  ⇒ 搬家必须与守卫改造**同一次提交**，并先证明"牙还在"（负对照）。
- **仍然不做多包** ⇒ 仍然放弃"客户端每组件一格开关"。
- M8–M10 是**新指标**，它们的第一版判据（BUNDLE-SPLIT §9 的 #17 / #18）本身就是 P2-7 / P2-8 的一部分
  —— 指标先于实现落地，与本仓"先有牙再拆/再收"的纪律一致，但不假装它们已经在跑。

## 重新考虑的触发线

1. **P2-7 落地后，"锚定边界"仍不可判据**（M8 到不了 100%、或 M9 到不了 0）⇒ 回来重议 D3 的手段
   （例如把静态对账改成运行期断言），而不是把指标悄悄放宽。
2. **P2-8 的守卫改造面远大于收益**，或路由账做不到逐条不变 ⇒ 回来重议 D4（退到"只在文档里声明归属"，
   并如实说明 M10 仍是 0 以外的值）。
3. **首屏 / 包体量成为用户侧首要抱怨** ⇒ 触发 [ADR-0003](../adr/) 写下的
   代码分割线，按 [ADR-0013](./0013-component-toggle-soft-goal-chunks.md) 重议包内懒块 —— 那时 D2 会被修订。
4. **客户端行级开关成为正式需求**，或出现只有多包能解的问题（独立版本 / 独立发布节奏）⇒
   按 [ADR-0012](./0012-bundle-multi-component-rows.md) 的触发线另写 ADR 重议方案 C。
5. **宿主开始支持子路径行各自的客户端半边**（组件级 `dsh.client`）⇒ ADR-0012 触发线 2 同款，
   重写一份 ADR 说明新形态。
