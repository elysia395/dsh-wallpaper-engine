# ADR-0015: 组件注入面 = 内核公开面的具名视图（修订 ADR-0014 D3① 的措辞）（component injection surface = a named view of the kernel's public face）

- **Date**: 2026-10-14
- **Status**: Accepted
- **Deciders**: 用户（产品口径）+ 实现（本仓，P2-7 落地时实测）
- **Amends**: [ADR-0014](./0014-goal-reanchor-and-contract-tightening.md) —— **仅 D3① 的措辞**：由「每一键都必须落在内核的**稳定面**」改为「每一键都必须落在内核的**公开面**（稳定面 **或** 内核为该组件具名声明、写进契约的**视图面**）」
- **Related**: [ADR-0002](../adr/)（设置的单一真源）、
  [ADR-0007](../adr/)（机器判据只针对代码与磁盘）
- **实施**: [`docs/wip/BUNDLE-SPLIT.md`](../) 的 §8「P2-7」动作 2 与 §9 #17；
  落地文件 `lib/kernel/component-session.js`（`COMPONENT_VIEW_KEYS` / `componentViewFrom` / `createComponentSession`）与 `test/verify-component-face.mjs`

## Context

- [ADR-0014](./0014-goal-reanchor-and-contract-tightening.md) 的 **D3①** 写的是：组件不再解构整个内核对象，
  改为消费显式列出的键，**且每一键都必须落在内核的稳定面**。
- P2-7 落地时实测：两个组件的视图里有一批键**只在某一个组件里用到**
  （`ABOUT_DIR` / `mascotDir` / `mascotPath` / `MASCOT_EXT` / `MASCOT_MAX_BYTES` / `avatarDir` / `avatarPath` /
  `AVATAR_SIDES` / `AVATAR_EXT` / `AVATAR_MAX_BYTES` / `traceMediaRequests` / `readWebShim` / `buildSeedScript`；
  逐条逐组件的真源是 `lib/kernel/component-session.js` 的 `COMPONENT_VIEW_KEYS`）。
- 而**稳定面的既有定义**是「被 ≥2 个路由族或门面共享基座消费的字段」（`lib/kernel/host-kernel.js` 文件头）。
  ⇒ 按字面执行只剩两条路：(a) 把这批键升进稳定面（= 把"被 ≥2 族共享"扩成"含组件私有键"），代价是**该定义失效**，
  且每新增一个组件都会让内核公开契约线性膨胀；(b) 为组件声明**具名视图面**，稳定面定义保持不变。
- M9 要治的是「**绕过注入面**直接消费内核对象」，不是「组件不许碰非稳定面字段」。
  视图面把依赖**显式化 + 双向对账**（M8 = 100%、M9 = 0 都能达到）；
  把这批键改叫「稳定面」只是换个摆放位置，并不增加任何解耦。

## Decision

- **D1 内核的对外面分两级**：**稳定面**（既有定义不变：被 ≥2 族 / 门面基座共享）+
  **具名视图面**（内核为某个消费者 / 组件**显式声明、写进契约、可机械对账**的子集）。
  两者合称**内核公开面**；**内部面** = 未出现在任一公开面里的字段。
- **D2 组件与路由族只能消费公开面**：不得直接解构 `hostKernel`。组件视图由
  `componentViewFrom(kernel, component)` 产出，**缺键即抛**（不许静默 `undefined`）；
  视图键集是**单一真源**（`COMPONENT_VIEW_KEYS`），声明与消费逐键对账。
- **D3 视图面不得成为「把内部面洗成公开面」的暗门**：① 视图键集必须显式落盘、可双向对账
  （声明 == 入口消费 ∪ 会话消费）；② 视图面规模设**棘轮**（只减不增，新增键必须写理由）；
  ③ 视图面里来自内部面的键必须在文档 / 阶段报告里**逐条列出**，不许含糊。
- **D4 不引入静默降级**：缺键抛错（与 ADR-0014 D3 的「缺键即抛」同款）。
- **D5 稳定面仍可扩，但按原定义**：只有当某键确实被 ≥2 族共享时才升进稳定面；
  组件私有键一律走视图面。

## Consequences

**收益**

- 稳定面保持 15 项，内核公开契约**不随组件数线性膨胀**；「稳定面」的定义继续成立。
- 组件的依赖从「整个内核对象（95 字段）」变成「具名、可对账、带棘轮的视图」，M8 / M9 有机械判据。
- 依赖关系被**显式化**：谁用了哪些内核字段，一眼可查（而不是散在 `const { … } = hostKernel` 里）。

**代价 / 我们放弃了什么**

- **放弃了「公开面 = 稳定面」这种单层级的简洁性**：现在有两级公开面，读者要先知道视图面住在
  `lib/kernel/component-session.js` 的 `COMPONENT_VIEW_KEYS`。
- **视图面暴露了一批内部面字段**（逐条落在 `COMPONENT_VIEW_KEYS` 里）—— 即「组件仍在依赖内核的内部实现」，只是依赖关系被显式化了。
  这是**有意保留的耦合**：真正解耦应当把**语义**（而不是名字）迁到稳定面或独立模块，
  而不是把键搬进稳定面。本 ADR 不为「看起来干净」付这份代价。

## 重新考虑的触发线

1. **视图面键数持续增长**（棘轮被迫放宽、或某个视图接近内核字段总数的量级）⇒ 回来重议 D1，
   考虑给该组件建立**独立模块边界**，而不是继续加视图键。
2. **出现第二个消费者需要同一批键** ⇒ 按 D5 升进稳定面（这是稳定面本来的定义）。
3. **守卫做不到「声明 == 消费」的双向对账** ⇒ 说明视图面退化成了新的散文，回来重议 D3。
4. **宿主开始支持子路径行各自的客户端半边 / 组件独立发布** ⇒ 与 ADR-0012 触发线 2 同款，另写 ADR。
